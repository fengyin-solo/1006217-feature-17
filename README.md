# 水电站机组运行检修管理平台

面向电站台账、机组运行、调速励磁、主变与闸门、大坝渗流位移监测、机组检修与发电计划的一体化水电站运行检修管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `hydropower-plant-om:entries` 这一项，或调用 `resetModule(模块)`。

## 技术供水的统一口径（两套取值只认一套）

技术供水存量里同时存在「台账定值」与「运行时段实测值」两套供水压力。规则由系统统一裁定：

- **两套并存且有争议时，以较晚产生的那一套为准**（比较两套各自的产生时间），统一成唯一的
  「供水压力」，原两套取值不保留中间态，并在「取值来源」列注明采用了哪套、在「备注」写明仲裁过程。
- 压力区间收窄（低压 `<0.20`、正常 `0.20–0.35`、高压 `>=0.35` MPa）与「按供水压力排布先后」
  读的是同一个统一字段，不会找的时候一套、排序时另一套。
- 列表收窄条件（系统编号 / 供水类型 / 压力区间 / 排序 / 页码）持久化在
  `hydropower-plant-om:cooling-query`，翻页、切到别的模块、刷新后回来都停在刚才那一页，不跳回第一页。
- 运营概览的「技术供水」行与列表共用同一条查询管线：异常系统数跟着收窄条件变；「另存当前结果」
  导出的条数与页面呈现条数一致。
- 同一系统编号重复登记按覆盖处理（只保留最后一版，不产生两条）；「落泄洪待办」按系统编号幂等，
  泄洪操作页的联动待办条数与运营概览随之变化。
- 存量迁移（`src/data/cooling-migration.ts`）：按登记时间迁移，缺登记时间按检查日期回填；
  早期没有供水类型的，以 `2021-01-01` 为界，早于该日归「机组冷却供水」，之后归「公用技术供水」；
  所有回填项都在「备注」标注「来源：存量迁移规则」；按系统编号去重，重复登记保留较晚登记的一条。
  本地仍是 v1 占位数据时，首次读取会自动迁移一次。
